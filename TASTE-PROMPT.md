# Метапромпт: смаки Мирослава і як з ним працювати над презою AI-Оператор

Вставити першим повідомленням у новій сесії разом із `EDIT-CHEATSHEET.md`. Це витяг із живої роботи 21–22.09.2026, а не теорія.

## Хто і що робимо
Замовник — Мирослав, пише українською, скорочено, часто голосом (у тексті лишаються обмовки: «хефотку» = «фотку», «Мишу» = «нішу»). Спікер — Влад Ясько, тексти слайдів російською. Дека — `preza-ai-operator/google180.html`, квадрат 1:1, дивиться в браузері на `?square&clean&s=N`.

## Що йому подобається
- **Візуал замість тексту.** Текстовий слайд для нього = недороблений. Кожен слайд має мати кадр, схему, живий сайт або відео.
- **Фотореалістичні 3D-рендери.** Прості SVG-іконки він назвав «дешево виглядає». Генерувати преміальні сцени (GPT Image 2.5, 2k, темна тепла палітра, жовтий акцент), а не піктограми.
- **Великі картинки.** Постійно просить збільшити, розгорнути на весь слайд, прибрати рамки і чорні смуги.
- **Живі елементи.** Сайт у вікні браузера з покроковою прокруткою, відео з автоплеєм, hover-нахил у 3D, клік для звуку або повного екрана.
- **Один рух на вхід.** Анімація коротка, до 1–2 секунд. Семисекундне малювання іконок просив скоротити до однієї.
- **Повний текст джерела.** Нічого не скорочувати і не вигадувати, особливо цифри.
- **Чорно-жовтий.** Фон `#0B0907`, акцент `#FDD506`, один акцент на заголовок через `<em>`. Зеленого немає.
- **Рівні відступи.** Поля 7cqw, текст вирівняний по центру або по осі з сусіднім блоком, нічого не налазить.

## Що йому не подобається
- Плашки та контейнери навколо кожного пункту, коли можна текст просто на фоні.
- Дрібні картинки в сітці, обрізані голови, чорні смуги в контейнері відео.
- Підписи-URL і технічні хвости під картинкою: просить прибирати.
- Однакові дублі слайдів, які прийшли білдами з Google.
- Довгі пояснення від мене. Хоче результат і один скрин.

## Як він формулює правки
Короткими фразами з посиланням на слайд: «прибери текст знизу», «вирівняй по центру», «зроби на весь екран», «додай стрілку», «поверни як було». Часто кидає скрин з обведеним місцем. Якщо каже «зроби три варіанти» — треба окрема сторінка з табами і живою анімацією, він обере літеру. Якщо правка конкретна — робити одразу в деці без варіантів.

## Що я використовую в роботі
- `python3 source/_slide.py N` — що це за слайд, oid, layout, body, рядки CSS.
- `python3 source/_edit.py N --reason "…" [--t …] [--b @file] [--b129 '{…}'] --bump` — патч, збірка, бамп версій.
- Правда про слайд — `source/overrides.json`, ключ `__visibleGoogleAudit.slides[oid]`. Частина слайдів розбита на `presentationParts.slides[i]`, тоді правити треба саме частину, інакше зміна не потрапить у деку.
- Стилі — `css/block-154-163.css`, layouts `s16-*`. Після зміни бампати `?v=` в `index.html` і `google180.html`.
- Скрини — `node shots/_cdp_page.mjs` з `URL`, `W`, `H`, `DELAY`, `OUT`, кроки через `STEPS` (JSON, всередині JS тільки одинарні лапки).
- Генерація картинок — `assets/gen-184-188/_gen.sh name "prompt"` (GPT Image 2.5, 1:1 або 21:9), потім `_fetch.py`. Референс обличчя Влада — `assets/photo/vlad-avatar.jpg`.
- Локальні копії сайтів у `assets/sites/<name>/` з мостом `RomaKP` для layout `s16-live`.

## Чого не роблю
- Не деплою без прохання, не чіпаю Google-презентацію.
- Не вигадую цифри й факти, яких немає в джерелі.
- Не ставлю зелений колір і не малюю примітивні іконки.
- Не роблю три варіанти, коли правка однозначна.
- Не пишу довгих звітів: результат, один скрин, версія для оновлення сторінки.

## Робочі граблі
- У тій самій деці паралельно працює інша сесія. Перед записом CSS і HTML перечитувати файл, overrides патчити читанням-записом одразу.
- Слайди з класом `sound` деко вмикає звук сама, для «без звуку» клас треба прибрати.
- `@keyframes` з `transform:none` в кінці скидають центрування, для появи використовувати анімацію лише по `opacity`.
- SMIL всередині SVG не керується через CSS, тривалість міняти в JS і перезапускати вузол.
- `drop-shadow` на розтягнутому SVG у Chrome ховає лінію.
- Кеш: після кожної правки бампати версії, інакше Мирослав бачить старе і каже «не працює».
